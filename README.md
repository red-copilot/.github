## README conventions · README 规范

Project READMEs should answer four questions quickly:

1. **What is this project?** State its purpose and current scope.
2. **What can it do today?** Distinguish implemented features from plans and limitations.
3. **How do I start?** Provide a minimal, maintainable quick-start path.
4. **How is it designed?** Link to authoritative architecture and operational documentation.

各项目 README 应帮助读者快速回答四个问题：

1. **项目是什么？** 明确定位与当前范围。
2. **现在能做什么？** 区分已实现能力、计划和限制。
3. **如何开始？** 提供最小且可维护的快速开始路径。
4. **架构如何设计？** 链接到权威架构与运维文档。

## Shared presentation · 统一展示约定

- Use the shared organization banner where it improves recognition. · 在适合的项目中使用共享 Banner。
- Place English first and Chinese directly below it. · 英文在上，中文紧随其下。
- Prefer architecture diagrams grounded in the actual implementation. · 架构图应反映真实实现。
- Keep badges factual, current, and verifiable. · 徽章应真实、及时且可核验。
- Do not claim tests passed unless they were actually run. · 未实际执行的测试不得宣称通过。
- Document security boundaries, permissions, failure modes, and known limitations. · 明确安全边界、权限、失败模式与已知限制。
