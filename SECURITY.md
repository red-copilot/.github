# Security Policy

Red Copilot projects are intended for authorized security research, controlled testing, and defensive engineering.

## Reporting a vulnerability

**Please do not publish exploitable details in a public issue before maintainers have had a chance to assess the report.**

Use the repository's **Security** tab and private vulnerability reporting feature if it is enabled. If private reporting is unavailable, contact the repository maintainers through a private channel available from the repository or organization profile. Do not include secrets or sensitive production data in an initial report.

Please include:

- affected repository, version, and commit if known;
- a concise impact assessment;
- minimal, reproducible steps in a system you own or are authorized to test;
- relevant logs or evidence with secrets and personal data redacted;
- any known mitigations.

## Scope and authorization

Only test systems for which you have explicit permission. Do not access, modify, or disclose third-party data while validating a report. Stop testing if authorization or scope is unclear.

## Response expectations

Maintainers will make a best-effort attempt to acknowledge and triage reports. Response and remediation timelines may vary by project capacity and severity; no fixed SLA is promised.

## Disclosure

Coordinate public disclosure with maintainers after impact and remediation have been assessed. Avoid publishing credentials, personal data, or details that unnecessarily increase risk to users.
